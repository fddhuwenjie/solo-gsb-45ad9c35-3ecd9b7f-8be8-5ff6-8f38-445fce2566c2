# PDF 遮盖工作台（本地 Redaction Workbench）

一个完全本地运行的 PDF 遮盖（涂黑/redaction）工具：上传最多 8 页的 PDF，
逐页预览、画出或删除**不透明遮盖框**，然后下载一份与当前预览一致的、
由**整页位图重新组成**的 PDF。

技术栈：**Python · FastAPI · PyMuPDF · 原生 JavaScript**（无前端构建、无外部 CDN）。

## 一条命令启动

需要本机已安装 Docker（含 Compose 插件）。

```bash
docker compose up --build
```

启动后在浏览器打开：

> **http://localhost:8000**

- 本机访问地址：`http://localhost:8000`
- 监听端口：容器内 `8000`，映射到宿主机 `8000`
- 若 8000 端口被占用，编辑 `docker-compose.yml` 中 `"8000:8000"`
  的左侧端口（例如 `"8080:8000"`），再访问 `http://localhost:8080`。

停止：`Ctrl+C`；后台运行：`docker compose up --build -d`；
查看日志：`docker compose logs -f`；停止并删除容器：`docker compose down`。

## 使用方法

1. 点击左侧 **选择 PDF**（1–8 页，≤100MB，未加密）。
2. **✏️ 画框**：在页面上按住鼠标拖出矩形，松开即添加；可切换黑/白/红/蓝/绿/黄。
3. **🩹 删除**：点击已有框即可删除；画框模式下悬停某框按 `Delete` 也可删除。
   侧栏列出本页全部遮盖框，可逐条删除或"清空本页所有框"。
4. 顶部按钮或 `←` `→` 翻页；`+` `−`、Ctrl+滚轮或"适应"按钮缩放
   —— **框以 PDF 点坐标存储，任意缩放下始终锚定相同内容**。
5. 勾选 **最终效果预览（服务器烘焙）** 可查看服务器端按下载路径生成的实际像素效果。
6. **逐页复核与定版交付**（见下节）：逐页确认服务器烘焙画面，全部确认后下载
   含位图遮盖 PDF 与 `manifest.json` 清单的 ZIP 定版包。
7. 也可以随时点击右上角 **⬇ 下载遮盖副本**，不经复核直接得到 `原名-redacted.pdf`
   （普通下载始终可用）。

快捷键：`D` 画框 / `E` 删除 / `←→` 翻页 / `+−` 缩放 / `Delete` 删除悬停框。

## 逐页复核与定版交付（定稿流程）

遮盖属于不可逆操作，本工作台提供"**逐页核对、确认定稿**"流程，保证交付包与
逐页核对过的画面严格一致：

1. 翻到某页，勾选 **最终效果预览（服务器烘焙）**，查看与交付完全相同的像素画面；
2. 点击侧栏 **✔ 确认本页**。确认会**绑定当时展示的那一版遮盖画面**（服务器通过
   预览响应头 `X-Box-Version` 发放版本令牌，确认时回传校验）：
   - 若该页的框在预览之后被任何请求（本人或其他标签页）增删 / 清空，版本即失效，
     页面提示 **「画面已过期」**，必须点 **重新预览** 取到最新烘焙画面才能确认，
     **不会把旧画面标成已复核**；
   - **没有任何遮盖框的页面也必须逐页确认**；
3. 侧栏「逐页复核」与顶部徽标实时显示每页 **待复核 / 已复核（绑定版本、框数）**，
   点击列表可直接跳转；
4. **全部页面确认后**，点击 **📦 定版交付（ZIP）**，得到 `原名-reviewed.zip`，内含：
   - `原名-redacted.pdf` —— 与逐页烘焙预览同一路径生成的位图遮盖 PDF；
   - `manifest.json` —— 各页**确认时的框数**、渲染 DPI、源文件名以及该 PDF 的
     **SHA-256**（侧栏同时展示摘要，便于核对）。

失效与一致性规则：

- **加框、删框、清空只使受影响页的确认失效**，其他页的确认保持有效；
  一旦有确认失效，**旧定版交付包立即撤销**（再次请求返回 409，无法下载过期包）；
- 复核、生成与编辑交错时，交付包**只可能对应同一版确认与同一份 PDF**：
  生成过程中若发生编辑会自动作废重来；补齐受影响页的复核后才重新发包；
- **停止修改后重复下载，得到字节完全相同的 ZIP、相同的包内 PDF 与匹配的 SHA-256**
  （服务器按确认签名缓存定版包，渲染本身也是确定性的）。

> 普通「⬇ 下载遮盖副本」、干净 / 烘焙预览以及 `docker compose up --build`
> 的启动方式均保持不变；定版 ZIP 是在其之上新增的交付通道。

## 输出 PDF 的安全保证

下载的副本**不是**在原页面上叠一个色块，而是按以下方式重建：

1. 原 PDF 的**每一页**（包括没有任何遮盖框的页面）都以 **200 DPI** 重新光栅化为位图；
2. 遮盖框直接**就地覆写位图字节**（含像素行填充，alpha 一并写成不透明），
   框内原像素被覆盖，无法从副本中恢复；
3. 用这些位图铺满全新页面，组成一份新的 PDF。

因此副本中：

- ❌ 不含原 PDF 的文字层（无法选中/搜索/复制遮盖区域的文字）；
- ❌ 不含批注、超链接、表单域、书签、附件（嵌入文件）；
- ❌ 不携带 Info 元数据与 XMP 元数据（标题、作者、制作工具等全部清空）；
- ✅ 保留原页数，每页可见尺寸（CropBox 显示尺寸）与方向（含旋转页）一致；
- ❌ 不是"在原页上叠色块"，遮盖区域没有任何可被移除的覆盖层。

> 注意：200 DPI 位图是栅格画面，放大到很大时会有正常的位图锯齿。
> 这是"像素不可恢复"的必然代价。

### 旋转页 / 裁切页为什么也准确

所有框都保存在**显示坐标系**（用户看到的、方向转正后的页面，单位 1/72 英寸点）。
光栅化时通过 PyMuPDF 的 `page.derotation_matrix` 把显示坐标换算回页面原始
(MediaBox/CropBox) 坐标再映射到位图像素；新页面尺寸取 `page.rect`
（即应用 rotation 后的显示尺寸）。因此 90/180/270 度旋转页、被 CropBox
裁切过的页面，框都能精确落在相同内容上。

## 输入校验（不覆盖正在编辑的文档）

- 非 PDF、文件损坏、内容流无法渲染 → 明确报错；
- 加密或带密码的 PDF（即使是空密码）→ 明确拒绝；
- 0 页或超过 8 页 → 明确拒绝；
- **只有当新文件通过全部校验后，前端才会切换会话**；上传失败时当前正在
  编辑的文档与所有遮盖框原样保留。

## 本地直接运行（不用 Docker）

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 隐私

文档仅保存在服务进程内存中，不写磁盘、不挂载任何卷；会话闲置 1 小时或
容器重启即消失。该工具设计为**本地单机**使用，默认也只建议绑定本机访问
（Compose 默认发布到所有接口；如需仅本机可访问，将端口改为
`"127.0.0.1:8000:8000"`）。

## API 概览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/upload` | 上传并校验 PDF，返回 session id 与页面信息 |
| GET  | `/api/{sid}/state` | 当前各页遮盖框 |
| GET  | `/api/{sid}/page/{n}.png?zoom=&redacted=` | 页面预览（干净 / 烘焙后）；响应头 `X-Box-Version` 为该页当前遮盖版本（复核令牌） |
| POST | `/api/{sid}/boxes` | 添加遮盖框（显示坐标点）；仅该页版本+1、确认失效、撤销旧交付包 |
| POST | `/api/{sid}/boxes/delete` | 删除指定框（同上，仅影响该页） |
| POST | `/api/{sid}/boxes/clear` | 清空某页（原本为空则不改变版本/确认） |
| POST | `/api/{sid}/review/confirm` | 绑定烘焙预览版本确认某页（版本不符 409，须重新预览） |
| GET  | `/api/{sid}/review/delivery` | 全部页确认后下载定版 ZIP（位图遮盖 PDF + manifest.json，含 SHA-256）；未全部确认或被编辑失效时 409 |
| GET  | `/api/{sid}/download` | 不经复核，随时生成并下载位图重组的遮盖副本 |
| GET  | `/api/health` | 健康检查 |
